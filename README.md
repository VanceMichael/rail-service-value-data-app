# 铁路复运中的货主服务缺口与改道取舍

业务资料均为合成记录。表头字段及跨表引用见 `fixtures/format.json`。

## 数据说明

日期按运输季起算，目标 P 的指定船期由 port-calls 提供。leg 用连字符连接起讫站，批量为千克，空车即便 max_kg 为零也占其车底时间。每一候选安排独立比较，同一车底腿必须时间连续可接，连续地点不同需有已提供的空车路段，装卸的准备时间资料以日精度表示。同日可接仅在同站。
road-survey 的 unknown 不许强制计入回流；range 记录可能应答窗口，不能等同于通过协议确认。obligations 标示签订时的最低运量和到站日。最低站频次是可办理的服务窗口，空车不计。
freight-profile 标注登记时采用的运输季型、货类和货主规模。当地季初天数以各季自己的日历记，wet 和 dry 不共用抽样分母。service-capture 登记每个站的登记范围、被访货主数、人群覆盖基数及获知日，群体行不是逐批需求。shipment-receipts 是目的站后续签收，held 只是已到站待交，accepted 才是交付。received_day 是现场日期，known_day 是回收回单的日期。

CSV 使用 UTF-8、逗号分隔，无引号与内嵌换行。未提供的字段是空字符串，作为关系值的 `-` 表示不适用。多值字段用竖线分隔，数值和日期单位见业务约定。

## 复运服务审议

`tools/service-review.mjs` 把托运登记、改走公路调查、已认领铁路承诺、分段车次与转运/回单放进同一套比较，供每期运行图调整前使用。仅用 Node.js 标准库。

```bash
npm run review                          # 每期审议包（方案比较 + 被压抑需求 + 改道状态）
npm run review -- allocate S2           # 单方案排程、分站频次、冲突与余量
npm run review -- allocate S0 --mode volume   # 只按装车量排序，暴露大站盖住小站
npm run review -- lot L2 --option S2    # 货主查询：交付窗口与失约原因
npm run review -- demand --segment C-P  # 按货类/货主规模的需求与登记时间范围
npm run review -- suppressed            # 被压抑需求，按证据等级与抽样覆盖
npm run review -- reconcile --option S2 # 回单核验（只认 accepted 签收）
```

各命令都支持 `--json`，公共参数 `--source <目录>` 与 `--as-of <日>`。

### 计法与边界

- **货批归属**：一个 lot 是一条货批；跨站短驳、分段改道仍记在同一 lot 下，需求按起讫归属，不生成新需求、也不重复计入。
- **状态区分**：铁路已收（accepted）、已认领承诺（promised）、已申报（reported）、承运商拒收（rejected）、主动改走（road）、已收但过期未运（expired）、到站待交（arrived-held）与已交付（delivered）分开报告。排程只排仍在铁路侧、尚未交付的货批；拒收与改走进入被压抑需求，重新受理后才计入车次。
- **被压抑需求**：只有 `confirmed` 且有意向窗口的记录计入确定回流；`range` 只进可能区间；`unknown` 或没有意向时间的公路记录不计。每行带证据日、证据龄、路线与抽样覆盖；wet/dry 覆盖不共用分母。
- **车底与路径**：有效载量取 `min(leg.max_kg, vehicle.total_mass_kg)`；空车 `max_kg=0` 占路径但不产生载量。同一车底按日衔接，同日只能同站接续，换站必须有已提供的空车路段。车底衔接不可行的方案只列容量预测，不报复运收益。
- **分配口径**：`service` 口径先保已确认承运窗口，再排必须整批的货，最后用余量装可拆批；`volume` 口径只按装车量排序，用于暴露小站与下游承诺被盖住的风险。整批按全有全无、可拆批按公斤部分装载，两者载量分开统计。
- **冲突**：已认领承诺在截期前到不了港时，输出缺口、晚到天数、瓶颈段余量、同段可回收载量，并列出“改道”和“调承诺”两个选项。改道在出现位移记录前只标 `proposed`，目的站 `accepted` 签收后才算完成。
- **频次与预测**：最低站频次按载货服务窗口计，空车不计；容量不足时同时标出哪些小站仍保留最低频次、哪些只有预测受益。
- **货主查询与回看**：方案审议后可查本批交付窗口与失约处理原因；经营分析按选定路段回看各货类/货主群需求范围，没有共同路段的货批列明不计入。
- **回单核验**：只用 `accepted` 的签收公斤与到站日验证当时预测；转运与到站待交不算交付。
- **外推界限**：比较只在有共同路段、同一运输季且在该季抽样覆盖内的货批之间成立；其它情况只解释不能外推到哪里。

## 资料检查

使用 Node.js 22.23.4，依赖仅为 Node.js 标准库。运行 `npm ci --ignore-scripts --offline` 准备工作区。

运行 `npm run check:materials` 检查合成交接资料的字段与记录引用。运行 `npm test` 检查交接资料的读取、校验与复运计法。
